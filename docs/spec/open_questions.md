## 13.1 Persistence — `id` is a handle, not a key + the `size`-dump primitive must die (★)

1. **RESOLVED (binding, §10.1/10.5 hybrid):** `CompositeKey{Version, LayoutId, ViewId, TypeIndex, Generation, ContentHash}` (content-addressed with scope + schema version; SHA-256 of stable bytes). `Version` prevents V3.7/V3.8 alias. Same `ViewId` with different `Type/Generation/ContentHash` (e.g., `VolumeSlice+MeshSlice` vs `Volume+Mesh`) never aliases — composite key differs; `ViewCompositor::reViews_` is `map<CompositeKey, ReView>` (flat, not `map<LayoutId,map<ViewId,ReView>>` nested; nested is retained as debug alias via `groupBy(LayoutId)`). See `docs/spec/persistence.md` §10.1 EOL row.
2. **RESOLVED (binding, §10.3/10.5):** Layout is **set-of-`ViewId`s + `LayoutId` version**, not `size` nor rect-set. `2D→3D` on same `ViewId` (`plane some→nullopt`, `itemIds` swap) is **content change → `ReView::setPlane(nullopt)+setItems` in place** (your stated preference, now binding); `erase+emplace` is forbidden. Window **size** change is per-`View` `ReView::ensureTarget` inner `ViewTarget` recreate, no map churn; **layout** change is insert/erase `ReView` entries. `Rect` swap (same `ViewId`s, rects permuted) is **not** a layout recreate — just two `ReView::setRect` + `ensureTarget` recreates inner `ViewTarget` at stable `ReView` address. See `persistence.md` §10.2/10.3 table.
3. **OPEN ★ (product):** If `AppSceneObject::id` is stable but the underlying `data::Mesh*` / `VolumeDataset*` pointer is reallocated (asset hot-reload), which identity does `AssetRegistry::byObject_` (`render/asset_registry.hpp:137`) and the broker registry compare — pointer, `id`, or `(id, contentHash)`? Same `id` now points at different bytes — must the `ReMeshObject` be recreated? **Tentative fix in §7 addendum:** `AssetStore` keyed by `(AssetId, contentHash, generation, scope)` — pointer-identity path is deprecated for `Volume`/`Image` and kept only for legacy `MeshGeometry` shim; contentHash change forces `Re*Object` recreate. Confirm hot-reload granularity before V3.6 lands.
4. **RESOLVED (binding, §10.4 per-field):** `generation` is **per-field** (`cameraViewGen` vs `planeGen` vs `materialGen` etc.), not per-object. `Camera::rotate(1°)` bumps only `cameraViewGen`; `MaterialMapper` cache hit (`materialGen==last`) skips. See `persistence.md` §10.4 per-field table; global `storeGen` is derived aggregate for early-out only.
5. **RESOLVED (binding, §10.4 hybrid):** Mutators (`Camera::rotate`, `setTransform`) bump their **field's generation** *and* `SceneStore::storeGen` via `bump(FieldId)` — fields are private with bumping setters; raw field mutation without setter is forbidden. `hash(fields)!=lastHash` is the second short-circuit (bit-identical matrices coalesced) after generation equality, not the primary dirty. See §10.4 "Who bumps".
6. **RESOLVED (binding, §10.4 hybrid poll+push):** `ViewSynchronizer::sync` is **poll-mostly with push opt-in (hybrid)**: per-frame poll on `storeGeneration()` early-out + bounded `dirtyFieldsSince()` scan; explicit `markDirty(ViewId, FieldId)` push for off-frame editor edits. `ViewSynchronizer` owns `IDirtyTracker` abstraction (DIP) so a future job executor can batch without editing synchroniser — OCP via executor. See `persistence.md` §10.4 + `broker.md` §11.3.
7. **RESOLVED (binding, §10.3/10.5):** Yes — "layout is `count/identity`, not `size`" means **exactly `ViewId`-set**, not `rect`-set; a rect swap is just two `setRect`s with `ReView` addresses stable and each `ViewTarget` reallocated in place. Confirm wording in §10.3 table is the binding contract.
8. **RESOLVED (binding, §10.5 keep-allocated):** `AppView{visible=false}` / `App*Object{visible=false}` — **KEEP `ReView`/`ViewTarget`/`FBO` + `Re*Object`/`ReLight` allocated** for fast re-show (`render` early-out `visible==false`); eviction is `Layout`-scoped arena free or explicit `compactHidden` on memory pressure/page discard. Same for hidden `ReMaterial`/`ReLight` that are hidden.

## 13.2 Views & Pages/Layouts (★)

9. **OPEN ★ (architect):** Is a `Page`/`Layout` a `vector<AppView>` snapshot, an `AppViewStore` keyed by `LayoutId`, or does `ViewCompositor` own the `LayoutId` version that the harness bumps on user action (`2×2 → 1×1`, split, close)? **Tentative in §10.2:** `LayoutSpec{LayoutId, vector<ViewSpec{ViewId, row,col,span,…}>}` + `AppViewStore` keyed by `LayoutId` (store owns version), `ViewCompositor::reViews_` keyed by `CompositeKey{Version,LayoutId,ViewId,…}`; harness `AppController::switchLayout(LayoutId)` bumps via `LayoutStore::setActive(LayoutId)`. Confirm store ownership before V3.1 header review.
10. **RESOLVED (binding, §10.5 hybrid-global-assets + per-page-views):** `AppSceneStore` is **global for assets** (`Mesh`/`VolumeDataset` content-hash dedup, `AssetStore` lives globally) + **per-page `ViewStore`/`LayoutStore`** for visibility (`itemIds` is page-local; a mesh hidden on page B remains in global `SceneStore` but page B's `ReView` doesn't `items` it). This hybrid is the binding V3.1 disposition — avoids per-page duplication of large assets while isolating view lifetimes cleanly. See `persistence.md` §10.2/10.5.
11. **RESOLVED (binding, §10.5 absolute View::rect + LayoutSpec relative):** Both — and not duplicated translation: `LayoutSpec{row,col,rowSpan,colSpan,weight}` (relative, serialisable, HiDPI-agnostic) **plus** absolute `ViewRect x,y,w,h` produced by `Layout::resolve(windowSize, dpi)` — `View::rect` stores absolute pixels (the `core::setViewport`/`IRHIFramebuffer::blit` lingua franca, `ReView::ViewTarget` size); `LayoutSpec` is the relative constraint input to `resolve`. No `AppRect→ReRect` 1:1 translator needed; `Layout::resolve` is the sole translator. Shared `shared/rect.hpp` (no GL) defines `Rect` used by both `app::View` and `render::View::ViewTarget`. **Remaining:** HiDPI `devicePixelRatio` normalisation (§13.8 Q34). See `persistence.md` §10.5.
12. **RESOLVED (binding, §10.5/§11 share-by-id):** `AppView`s **share by `id`** (one `AppMeshObject` instance in `global SceneStore`, two `AppView::itemIds` reference it). Copy-by-value would duplicate large `data::Mesh*` refs and `MaterialDesc` and desynchronise edits (two projections of same mesh must stay in sync for slice↔3D crosshair — FR-app.3). Per-`ReView` cache duplication is intentional and correct — `ViewMapper` produces **per-View** `Re*Object` (see §11.4 `View owns the plane`, §13 Q29: per-View duplicates `Re*Object` so each `ReView` can carry different `ClipPlane`-derived `ReMeshSliceObject`). Share-by-id + per-View Re is the binding.

## 13.3 Materials — Even `IMaterial` Hierarchy (★ — SOLID LSP/ISP, now binding per §12)

13. **RESOLVED (binding, §12.2):** Tree is **role-segregated:** `IMaterial{min isTransparent}` → `IColorMaterial`→`MeshMaterial(abstract→{Phong,PBR})`, `IVolumeMaterial`→`VolumeMaterial`, `IColorMaterial`→`SliceMaterial`, `ILineMaterial`→`ContourMaterial`. `SliceMaterial` is a **sibling of `MeshMaterial`** (not reuse): distinct (`capping` lives only on `SliceMaterial` — ISP; `SliceRenderer` doesn't switch on `MeshMaterial` flag). `MeshMaterial` itself is **abstract** (never instantiated, only `Phong`/`PBR` (+future `Toon`…) concrete) — satisfies LSP (no instantiation of abstract that narrows postcondition) and OCP (new Mesh material = new file). See `materials_lights.md` §12.2 hierarchy.
14. **RESOLVED (binding, §12.2):** `app/` **mirrors the same tree as variant** (`app::MaterialDesc = variant<MeshMaterialDesc{PhongDesc|PBRDesc}, VolumeMaterialDesc{TFDesc+stepLength+shading}, SliceMaterialDesc, ContourMaterialDesc>`), not a flat discriminated struct. Variant gives header-only `scene/` (no vtables) + OCP (new desc = new alternative + mapper file, no edit to existing descs) + ISP (flat would force Volume to carry `shininess`). `Re*Object` kind is not used for discrimination — app's variant alternative determines the correct mapper/RE subtype (DIP: `broker` visitor dispatches).
15. **RESOLVED (binding, §12.2):** **By-value default + `MaterialId` opt-in.** `AppMeshObject { MaterialDesc mat; }` by-value (SRP, OCP for per-object materials; mutation `shininess 32→64` dirties **only** `MaterialMapper` via value-hash dedup — `hash(baseColor,shininess,…)`, sharing one `ReMaterial*` across identical descs). Opt-in `MaterialId → MaterialStore` for shared themes (global edits dirty `MaterialStore` + every `MeshObjectMapper` referencing it). Mapper doc must state dedup strategy.
16. **RESOLVED (binding, §12.5):** **Beside it:** `VolumePresentation{ VolumeMaterialDesc, TransferFunctionDesc, stepLength, shading }` — `TransferFunction` lives **beside** `VolumeMaterial` (not inside). ISP/OCP: TF has separate cache key/lifecycle and separate mapper (`TransferFunctionMapper`); bundling forces `MaterialMapper` dirty on TF edit and vice versa. Renderer boundary (`VolumeRenderer` takes TF separately today) kept; `volume_object_mapper` composes both mappers.
17. **RESOLVED (binding, §12.2/☆ closed):** **Distinct `ShaderProgram` branches** — `ContourMaterial` / `SliceMaterial` are distinct branches (not a `MeshRenderer` flag). Distinct adds mapper files but gives correct `IMaterial` subtype per `IRenderable` without view-switching (ISP), and keeps shader permutation cache key stable for future batching. Tracking as `render/material/shader_table.md` predecessor for V3.7.

## 13.4 Lights — Per-`View` Multi-Source Multi-Type, Same Broker Abstraction (★ — SOLID LSP/ISP, now binding per §12.3)

18. **RESOLVED (binding, §12.3):** Type set is **`Directional`/`Point`/`Spot` + reserved `Area`/`Environment` later (OCP via variant alternative).** Field list per type is pinned for header closure: `DirectionalLightDesc{dir,color,intensity,castShadows}` / `PointLightDesc{pos,color,intensity,radius,attenuation[3],castShadows}` / `SpotLightDesc{pos,dir,color,intensity,innerCone,outerCone,radius,castShadows}`. `ContourMaterial` stipple stays on material (ISP). Adding `AreaLightDesc` later = new variant alternative + `area_mapper.*` file, zero edits to existing mappers.
19. **RESOLVED (binding, §12.3 inline default):** **`AppView::lights` is `vector<LightDesc>` inline by default** (a light tweak still dirties only `LightMapper` cache via per-field `lightsGen`+`ContentHash` — not whole `View` — see §10.4 per-field split, so `LightId` indirection is not needed for dirty granularity). `vector<LightId>` indirect via `LightStore` is retained as opt-in for shared-light themes (same tradeoff as `MaterialId`). Headless tests that only mutate lights depend only on `LightMapper` cache, not on `View` (ISP).
20. **RESOLVED (binding, §12.5 world space):** **World space.** `AppLight::pos/dir` are world-space (`dirWS`/`posWS` in `ReLight`); `LightMapper` forwards; view-space `dir` needs are not a `LightMapper` concern — shader multiplies by `uView` (SRP). `TranslateContext{viewMatrix}` is available but unused by default (documented contextual opt-in for future `ViewSpaceLight` variant). See `materials_lights.md` §12.5.
21. **RESOLVED (binding, §12.3):** **`ReView::setLights(vector<ReLight>)` once before `items→drawLayer`** (not per-`ReMeshObject`). Matches `MeshRenderer::opaqueProgram` uniform setup (`render/mesh_renderer.cpp:32`) and ISP (per-object lights would duplicate uniforms and couple `ReMeshObject` to light count — ISP fat). Per-object lights remain a future `ReMeshObject::localLights` opt-in, not the default `ReView` composition.
22. **RESOLVED (binding, §12.3 2D unlit default):** **`AppView::plane present → default `shading=false`** (unlit, straight TF sampling like `app/mpr_slice.cpp:36`), overridden per-item by `AppVolumeSliceObject::pres.shading` / `AppMeshSliceObject::mat` when the View hosts mixed shading (the override is typed in `VolumePresentation{shading}` not on the View tag). `ViewMapper` default is `2D→shading=false` unless `pres.shading==true`.

## 13.5 Translators/Brokers — Heavily Abstracted Per-Type Mappers (★ — SOLID, now binding per §11)

23. **RESOLVED (binding, §11.2 two-type):** **`IMapper<AppT,ReT>` templated on TWO types** — explicit `IMapper<app::MeshObject, render::ReMeshObject>` per distinct app type. One `AppMeshObject` mapping to `ReMeshObject` vs `ReMeshSliceObject` per View plane does NOT violate: the two `ReT`s come from **two distinct `AppT`s** (`AppMeshObject`→`ReMeshObject`, `AppMeshSliceObject`→`ReMeshSliceObject`) — `View` plane determines which `AppT` is in `AppView::itemIds` (2D=SliceObjects, 3D=Objects), not one `AppT` polymorphic to two `ReT`s (LSP-preserving; two-type keeps substitutability clear). Trait `ITranslatorFor<AppT>` is rejected.
24. **RESOLVED (binding, §11.3 type_index):** **`Broker` keyed by `std::type_index(typeid(AppT))` + factory `registerMapper`**, not `enum`. Enum violates OCP (new kind edits enum + all switches) and is closed; `type_index` is open (new `AppT` adds a registration line). RTTI coupling is bounded (compile-time `typeid` of complete type, no dynamic dispatch) and `type_index` is auditable via `Broker::registeredTypes()` debug dump. Enum retained as `MaterialKind`/`LightKind` debug enum only, not as registry key.
25. **RESOLVED (binding, §11.4 TranslateContext):** **`IMapper::map(const AppT&, const TranslateContext&)` gains `TranslateContext{ const ClipPlane* viewPlane, glm::mat4 view, volumeModel, dims, meshBounds }` second arg** — contextual mappers (`MeshSliceObjectMapper` reads `viewPlane`, `PlaneMapper` reads `volumeModel+dims`) depend only on the segregated context they need (ISP), not on full `ReView*`. `app::PlaneDesc(Space::VoxelIndex)` is normalised to world **inside** `PlaneMapper` using `TranslateContext` (world is the stable `Re` ClipPlane) — callers don't pre-convert (SRP). `TranslateContext` with null `viewPlane` is valid for 3D (LSP: 3D mappers ignore it).
26. **RESOLVED (binding, §11.3 owned-once):** **`Broker` owns concrete mappers as `unique_ptr<IMapperBase>` created once on startup** (registry `registerMapper` at `AppContext` init). Per-`AppView` lazy creation is rejected (it would fragment `MaterialMapper` dedup caches and `LightMapper` sharing; ISP also fails — per-View mappers would expose synthesis policy to `ViewMapper`). `ViewSynchronizer`/`ViewCompositor` similarly are composition-root singletons per `AppContext`, not per-View.

29. **RESOLVED (binding, §10.5/§11.4 per-View):** **Per-View duplicated `Re*Object`s** — when two `AppView`s share the same `data::Mesh*` (`Slice` `2D` + `3D` both reference `boxMesh`), each `ReView` owns its own `Re*Object` (duplicate) so each can carry a different `ClipPlane`-derived `ReMeshSliceObject` per "View owns the plane" (§11.4). Sharing with a per-draw plane param would couple `ReMeshObject` to draw-time plane (ISP fat per-draw signature + SRP mixing) and complicates `ITransparencyPipeline` per-View sorting. Per-View duplication is the binding (matches `ReView::items` type-erased `IRenderable` composition — shared asset via `AssetHandle`, distinct wrapper).

## 13.7 Priorities & Sequencing (★)

30. **RESOLVED (binding, §9.1 addendum — now requires spec patch):** **Build order is `scene/ (V3.1)` → `CompositeKey+IDirtyTracker+ViewTarget abstractions (V3.5 slice)` → `broker/ IMapper/IViewBridge/TranslateContext skeleton (V3.2 skeleton)` → `Camera (V3.3)` → `View/ReView/ViewMapper/ViewSynchronizer/ViewCompositor (V3.4)` → then `persistence full (V3.5)` → `asset store (V3.6)` → `material/light evenness (V3.7)` → `RE-minimal (V3.8)`.** The prior "product-first persistence after mappers" ordering violated SOLID seeding: `*Mapper` written before `CompositeKey`/per-field generations existed would be rewritten. ## 13.8 SOLID / EOL sustainment grill — added by V3 spec-review (binding web research, V3 anal re-review 2026-08-23)

References as in `docs/spec/broker.md` §11.6 table (fetch-verified 2026-08-23). Single-language GLSL until `core/rhi/` lands via `RE_GLSL_VERSION` (SPEC §8); **SPIRV-Cross cross-compilation is allowed as preprocessing step** (GLSL→SPIR-V at build time), not runtime (binding). `core/draw::blit` → `IRHIContext::blit` (SPEC §9 V2.4 façade preserved). Block cleared for V3.1 header inventory; implement `core/rhi/gl/` first, `core/rhi/vulkan/` drop-in later (OCP via factory, zero `render`/`broker` edits).

32. **RESOLVED (binding, `nfr.md` RHI caps, §11.6 EOL-1):** **Capability query & graceful degradation (OCP, EOL).** Capability table pinned: `{ bool geometryShader; bool ssboAtomics; uint32_t maxTexture2DSize, maxTexture3DSize; bool bindlessTextures; bool computeShader; uint32_t maxColorAttachments; uint32_t maxLayers; }` (O3DE `isFeatureSupported` + QRhi `Feature` + Adept caps). **Degrade is typed `Result<void>` error `Error::Unsupported` surfaced by `ViewCompositor`** — not silent best-effort — because SPEC §5 mandates typed errors (no silent failure) and silent degrade hides capability loss from app (product recommendation binding; silent degrade would violate DIP error contract). Degrade table: `!geometryShader` → `SliceRenderer` CPU clipping + `MeshRenderer` fallback; `!ssboAtomics` → `LinkedListOIT` → weighted-blended OIT; `volumeSize>maxTexture3DSize` → halve res or tile (NFR §5). `ReView::render()` returns typed `unsupported` that `ViewCompositor` logs via spdlog and skips that layer (visible in balance sheet, not crash). **Open follow-up (product confirm):** confirm weighted-blended OIT fallback is the desired OIT degrade (vs no transparency).

33. **RESOLVED (binding, `broker.md` §11.2.1, `modules.md` DIP):** **SRP/ISP for `IMapper` & `IViewBridge` (header names).** `i_mapper.hpp` declares **both** `IMapper` + `ICachedMapper : IMapper` together (single header, ISP-segregated by inheritance) for include simplicity; `i_cached_mapper.hpp` is retained as *alias include* (`#include "i_mapper.hpp"`) so existing `broker_per_type` audit stable. `IViewBridge` is segregated into `ISyncBridge{sync}` + `IRenderBridge{renderAll,presentAll}` with `IViewBridge : ISyncBridge, IRenderBridge` (composition, not multiple inheritance diamond — both are pure interfaces). Headless `tests_sync_only` includes only `i_sync_bridge.hpp` (DIP/ISP for test double; NDepend ISP). **Binding:** `i_mapper.hpp` + `i_view_bridge.hpp` (`ISyncBridge`+`IRenderBridge` inside) + `i_sync_bridge.hpp` alias; `broker.hpp` exposes `Broker::get<T>()` returning `IMapper<T>*` (pure) where possible.

34. **RESOLVED (binding, §10.5 + `persistence.md` HiDPI, NFR §5):** **Layout HiDPI & `devicePixelRatio` (EOL).** `Layout::resolve(framebufferSize, contentScale)` takes **physical framebuffer size** (`glfwGetFramebufferSize`, not `glfwGetWindowSize`; `glfwGetWindowContentScale` for per-monitor scale) — web.dev high-dpi 2025-04-14, MDN `devicePixelRatio`, GLFW #1857 + vispy #99 framebuffer vs window size. `View::rect` stores **physical pixels**; DPR is therefore *implicit* in rect — monitor move re-triggers `Layout::resolve` + `ViewTarget` recreate only (no extra `dpr` field in `CompositeKey`; `CompositeKey{rect}` hash already changes via physical rect). `LayoutSpec{row,col,span,weight}` relative-weight normalisation: `weight` = flex (remaining space after fixed `span`), `rowSpan==0` = fill remainder, equal weights → equal distribution, remainder pixels to last view (deterministic rounding). **Binding:** `contentScale` not stored in `CompositeKey` version — physical `rect` is the key.

35. **RESOLVED (binding, §7 addendum + §10.5 + `nfr.md` EOL-3):** **Asset Store sharding & ref-count/GC (SRP, EOL).** **Dual-key transition for V3.6 (binding):** `VolumeDataset`/`Image` migrate **atomically** to `AssetId+contentHash` (global store, `LayoutId`-scoped arena per `CompositeKey` version); `MeshGeometry` keeps **pointer-identity `byObject_` shim alongside `AssetId` during V3.6** (dual-key: `byObject_` for legacy `MeshRenderer` path + `AssetId` for new `SceneStore` path) with deprecation note — shim removed in V4 when all mesh paths use `SceneStore`. Eviction: **`LayoutId`-scoped arenas + LRU within arena + ref-count zero → deferred GC until `compactHidden` or layout discard** (not immediate free) — impacts `ReView` hidden-keep memory ceiling per §10.5 (keep-allocated default). Ref-counts are `std::atomic<uint32_t>` even under inline `IJobExecutor` (data-race-free per NFR §5; `AssetStore` counters guarded by `atomic`, not `mutex` — `atomic` cheaper for single-threaded inline executor and correct for future `ThreadPoolExecutor`). **Binding:** dual-key for `Mesh` this cycle, atomic counters, deferred GC.

36. **RESOLVED (binding, §10/§11.6 EOL-4 + DCS Data Contracts 2026-05-26):** **Serialization & `CompositeKey` schema evolution (EOL).** Wire format pinned: **JSON (text) + binary blob (NRRD raw `uint16` block) + SHA-256 `contentHash`** for `VolumeDataset` dims/contentHash; `SceneStore::serialize()` writes JSON with `Version` migrations via `SceneMigrator{Version→Version}` chain — OCP for schema (new version adds one `Migrator` file + one `registerMigrator` call, zero edits to existing migrators; DCS Data Contracts versioning). **No `Re*` caches are serialized** (they are reconstructible via `ViewSynchronizer` replay); only stable wire: `SceneStore` (`Id+gen+hash` per object), `MaterialDesc`/`LightDesc` (stable variant JSON), `LayoutSpec`/`ViewDesc` (relative), `Camera` (`view/proj` matrices). Schema evolution: backward/forward/full compatibility per Confluent Schema Registry modes — V3 mandates **BACKWARD** (new reader reads old writer) for `SceneStore` file format (spec file must remain readable to EOL). `Version` prefix in `CompositeKey` invalidates broker cache on migration (hierarchical `Version:LayoutId:Type:Hash`).

37. **RESOLVED (binding, `nfr.md` §5 + `persistence.md` §10.4, Adept RHI threading):** **Threading model & `IJobExecutor` contract (DIP/OCP, EOL).** `core::IJobExecutor{ void execute(Function<void()> f); void parallelFor(size_t n, Function<void(size_t)> fn); }` is **header-only concept with inline synchronous fallback** (`execute(f){f();}`) — no thread pool allocated today, keeps ASan/UBSan 1-thread determinism + deterministic rendering (FR NFR). `ViewSynchronizer::sync` / `Broker::parallelFor` / `AssetStore::registerAsset` are DIP-behind `IJobExecutor` + `IDirtyTracker`; future `ThreadPoolExecutor` (V4) injected without editing `render`/`broker`/`scene` (OCP). **Data-race-free now:** `AssetStore` ref-counts `std::atomic<uint32_t>` (even under inline executor); `ReView` list mutation is **externally synchronised** (`sync` happens-before `renderAll` happens-before `presentAll`) — documented in headers as `thread-compatible` (not `thread-safe`) for `ReView`/`ReSceneObjects`, `thread-safe` for `AssetStore`+`SceneStore` counters. **Binding:** `ITransparencyPipeline::begin/end` **is allowed** to dispatch compute jobs via `IJobExecutor` (explicit — pipeline owns no thread, executor injected; `begin` may `parallelFor` OIT clear, `end` may `dispatchCompute` sort). No `mutex`/`thread`/`async` in render hot path until `IJobExecutor` is `ThreadPoolExecutor`.

38. **RESOLVED (binding, `broker.md` §11.6 LSP-3 + `modules.md` OCP, Here Be Braces):** **IRenderer LSP & `IRenderable` type-erasure (LSP/OCP).** Concrete erasure is **`ITypeErasedDraw{ virtual void drawLayer(const Camera&, IRHIFramebuffer&, DrawContext&)=0; }` with type-erased ownership `unique_ptr<ITypeErasedDraw>` in `ReView::vector<IRenderable>`** — not `std::function<void(...)>` (which would per-draw allocate and lack `AssetRegistry*` ownership; `ITypeErasedDraw` holds `AssetHandle`+`ReMaterial*`+`model` per Re object, mirroring `Re*Object` inventory). Header `render/i_renderable.hpp`. `ReView::addItem<SceneT>(SceneT)` enforces **`requires Renderable<SceneT>` concept (`requires requires(SceneT s){ { s.drawLayer(...) } }`) at `addItem` time — compile-fail** (LSP: strengthen postcondition at compile time, not runtime `Broker::get` typed error). Legacy untyped `addItemVariant(variant)` path returns `Broker::get` typed error (SPEC §5) for `tests_direct` that still use variant scene dispatch (regression lock). **Binding:** `ITypeErasedDraw` virtual, compile-fail concept; `IRenderer::render` retained **only for direct tests** (not for `ReView` compositing), LSP hole closed for V3.4.

## 13.9 New SOLID/EOL grill — V3 anal re-review gaps (must resolve before V3 implementation, web-verified 2026-08-23)

> These BLOCK V3 kickoff in addition to §13.8. Each was found by anal SOLID/EOL re-review of future scope items T1..T10 (V3.1..V3.9) against web-verified SOLID definitions. Each is marked with the solid principle it violates and the fixing section/s.

39. ★ **SceneStore/SceneStore God-object & bounded context (SRP — risk):** `SceneStore` currently owns `AssetId` handles + per-field `generation` + `ContentHash` + `storeGen` + `Scope/LayoutId` arena + `serialize()/deserialize()` — 6 reasons to change (identity vs generation policy vs hashing vs scope vs serialization). By Martin Clean Architecture "one actor, one reason to change" + ICS SRP + God Object anti-pattern (dilankam 2024), this is a God object risk. **Recommendation (binding, DDD bounded context):** Keep single `SceneStore` as one aggregate root per DDD bounded context (Software Patterns Lexicon bounded contexts — one layout/page actor owns scene lifecycle) because all 6 responsibilities share one actor (scene team) and splitting into `HandleRegistry+GenTracker+HashCache+ScopeArena` would multiply indirection without actor separation (see `modules.md` SRP bounded-context justification + `persistence.md` §10.4 "Who bumps" single `bump(FieldId)` entry point). **Mitigation:** single entry point `SceneStore::bump(FieldId)` + per-field `generation` split + `storeGen` aggregate for early-out only; `AssetStore<T>` typed template handles `AssetId` sharding separately (SRP via `AssetStore<T>` per kind). **Open:** Confirm the team keeps one owning team for scene graph through EOL; if a separate persistence team emerges, split `SceneStore` into `SceneHandleStore` + `GenerationStore` (deferred to Q39 review trigger when actor splits — see `broker.md` §11.6 SRP-3).

40. ★ **TranslateContext fat vs segregated (ISP — was hidden violation):** Prior `TranslateContext{viewPlane,view,volumeModel,dims,meshBounds}` forces every mapper to depend on fields it never uses — `CameraMapper` forced to depend on `volumeModel+dims` (ISP fat `Worker` — Baeldung ISP + NDepend ISP). **Fixed (binding) in `broker.md` §11.4.1:** `TranslateContext{ ViewContext view; optional<VolumeContext> volume; }` where `ViewContext{viewPlane,viewMatrix,projMatrix}` is needed by all, `VolumeContext{volumeModel,dims,voxelSpacing,meshBounds}` only where `Space::VoxelIndex→world` needed (`PlaneMapper`, `VolumeSliceObjectMapper`). Mappers touch only their role; `hasVolume()`/`hasPlane()` keeps LSP preconditions weak (code-note-vr LSP). **Open:** Header review must verify no mapper touches `volume` unless `hasVolume()` true (audit: grep `TranslateContext` use in `camera_mapper` should be zero `volume`).

41. ★ **Broker ↔ render DIP ACL vs pure inversion (DIP — clarification):** `broker/` includes concrete `render::ReMeshObject` type names for `IMapper<AppT,ReT>` — looks like high-level policy (broker) depends on low-level concrete (render), violating DIP inversion diagram (Baeldung/Oleksii Tym "policy owns abstraction"). **Decision (binding, ACL pattern):** `broker/` is an *anti-corruption layer* (DDD Bounded Context ACL — Software Patterns Lexicon) that *defines* the stable `IMapper`/`IViewBridge` abstraction; `render/` concrete `Re*` satisfies the concept via factory registration `Broker::registerMapper<AppT,ReT>(make_unique<ConcreteMapper>())` at composition root `AppContext`. Dependency on concrete names is *knowledge* not *ownership* — stable interface lives in `broker/`; `render/` never depends on `broker` internals beyond the concept. Pure opaque-handle inversion (`broker` defines `RenderableHandle` opaque, `render` maps handle) is deferred to IRHI migration where `IRHIFramebuffer/IRHITexture` handles replace `Re*Object` (see §11.2.2 DIP ownership). **Open:** Product must accept ACL as DIP-compliant under DDD for this EOL horizon (pure inversion would postpone V3.2b).

42. ★ **Material/Light `std::variant` closed-for-types OCP trade-off (OCP — was unquantified):** `MaterialDesc variant<Phong,PBR,Volume,Slice,Contour>` and `LightDesc variant<Dir,Point,Spot>` are *closed for adding types* (variant list edit) but *open for adding operations* (new visitors) — opposite of polymorphic hierarchy (open for types, closed for operations) per Here Be Braces 2020-06-26 + nordvarg 2025 + StackOverflow variant vs virtuals. Adding `ToonMaterial` edits one variant alias + one visitor overload (one file edit) but zero edits to existing concrete `*Mapper` files/`ViewMapper` — bounded OCP cost. **Decision (binding, §12 + broker §11.3.2):** Variant stays for V3 because type set is closed/small (4 materials, 3 lights, bounded per SPEC §1 Phong-only non-goal) and operations (visitors/dispatch/dedup) vary more than types; polymorphic hierarchy retained for `render::IMaterial` concrete tree where new `ToonMaterial` = new file open for extension (see `modules.md` OCP). Variant cost is acceptable; future EOL with many kinds can migrate `app::MaterialDesc` to polymorphic hierarchy without touching `ViewMapper` (OCP via `Broker` factory). **Open:** Product must accept one-file variant edit as OCP-compliant for this closed set.

43. ★ **`DrawContext` global static vs per-`FrameContext` instance (SRP + test determinism — was `invalidateDrawCache` global):** `core/draw.cpp` static `setViewport/setClearColor` cache with `invalidateDrawCache()` is global mutable state — SRP violation (one global reason to change per every frame) and test-determinism violation (tests must call `invalidate` to avoid cross-test pollution). **Fixed (binding, `modules.md` RHI + `nfr.md` EOL-5):** `DrawContext{Viewport,ClearColor,Depth,Blend,spy}` instance per `FrameContext` replaces global cache (SRP via instance per frame; spy per context, not global). `invalidateDrawCache()` removed; `DrawContext` reset per frame. `core::Draw` façade delegates to `DrawContext&` passed from `FrameContext` (DIP: render depends on `DrawContext` abstraction, not static). **Open:** Header review must verify no `static` cache remains in `core/draw.cpp` after V3.2a.

44. ★ **`ReView` composition vs God object (SRP — `rect+camera+plane+lights+items`):** `ReView` holds `rect+Camera+Plane+Lights+vector<IRenderable>` — 5 fields, could be God object (different actors: camera team vs lighting vs geometry). By ICS SRP "different actors → different classes", is `ReView` God? **Decision (binding, `modules.md` SRP + `broker.md` §11.3.1):** `ReView` is *not* God — its single actor is "view composition" (one View per screen section, one layout team). Lights vs camera vs items are *not* separate actors here because they are all "view composition" requested together per layout (MPR 2D slice vs 3D perspective validated together per mapper). `ReView` delegates FBO lifecycle to `ViewTarget{IRHIFramebuffer}` (SRP via composition) and per-field generations keep `ViewSynchronizer` cache split (ISP). `ReView` changes only when view composition contract changes (one reason). **Open:** None — documented.

45. ★ **`IRenderable` erasure mechanism & `IRenderer<T>` concept (LSP/OCP — was vague "type-erased draw"):** Prior "type-erased draw (`concept Renderable<T>: void drawLayer(...)`)" did not name erasure: `std::function` vs virtual `ITypeErasedDraw` vs handle. `std::function` would per-draw allocate and hide `AssetHandle` ownership; `IRenderableHandle` owning `AssetRegistry*` couples `ReView` to registry lifecycle. **Fixed (binding, §13 Q38 + `modules.md` OCP):** `ITypeErasedDraw{ virtual void drawLayer(const Camera&, IRHIFramebuffer&, DrawContext&)=0; virtual ~ITypeErasedDraw()=default; }` with `unique_ptr<ITypeErasedDraw>` in `ReView::vector<IRenderable>`; each `Re*Object` maps to one `ITypeErasedDraw` impl (`ReMeshDraw`, `ReVolumeDraw`, etc.) holding `AssetHandle/ReMaterial*/model/bounds`. `ReView::addItem<SceneT>` enforces `requires Renderable<SceneT>` at call site (compile-fail), legacy `addItemVariant` returns typed error (SPEC §5). **Open:** Header review must name file `render/i_renderable.hpp` and verify `Renderable` concept.

46. ★ **AssetStore sharding: `Mesh` dual-key & `LayoutId` arena eviction (SRP, EOL — was product-open):** Q35 left dual-key (pointer vs `AssetId`) and eviction (LRU vs immediate vs deferred) open. **Decision (binding, §7 addendum + §10.5, web-verified cache-key versioning):** `Volume`/`Image` atomically to `AssetId+contentHash` (global store, `LayoutId`-scoped arena); `Mesh` keeps dual-key `byObject_` shim + `AssetId` in V3.6 with deprecation (see Q35 RESOLVED). Eviction is `LayoutId`-scoped arena + LRU within arena + deferred GC until `compactHidden` or layout discard (not immediate free) — balances hidden-keep fast re-show (§10.5) vs memory ceiling. **Open:** Product must confirm dual-key for `Mesh` this cycle vs atomic migration (default is dual-key).

47. ★ **Serialization `SceneMigrator` chain & wire stability (EOL, §13 Q36 — was open codec):** Prior `Version` migrations had no codec chain. **Fixed (binding, §10/§11.6 EOL-4, DCS Data Contracts 2026):** `scene::serialize()` JSON (text) + binary NRRD raw blob + SHA-256 `contentHash`; `Version` migrations via `SceneMigrator{Version→Version}` chain (OCP via `registerMigrator` factory, zero edits to existing migrators) — new schema version adds one `Migrator` file. `Re*` caches *not* serialized (reconstructible via `ViewSynchronizer` replay); `MaterialDesc`/`LightDesc`/`LayoutSpec` stable wire (variant JSON with `kind` discriminator). Backward compatibility per Confluent `BACKWARD` mode — old file readable by new `SceneStore` (EOL file format must remain readable). **Open:** Product must pin JSON library (pinned `nlohmann/json` vs `glaze`) before V3.6.

48. ★ **Broker `type_index` RTTI & `AssetStore<T>` template extensibility (OCP/DIP — was enum vs type_index trade-off):** Enum `AppObjectKind` violates OCP (Meyer PV) but `type_index(typeid(AppT))` introduces RTTI coupling. **Decision (binding, §11.3.2):** `Broker` stays `type_index` + factory `registerMapper` (OCP via open registry). RTTI bounded: compile-time `typeid(complete type)` , no `dynamic_cast`, auditable via `Broker::registeredTypes()` debug dump; enum retained as `MaterialKind`/`LightKind` debug enum only (not registry key). `AssetStore<T>` typed template (`AssetStore<Mesh>`, `AssetStore<VolumeDataset>`) keeps extensibility to new asset kinds without per-kind duplicate (SRP per `T`). **Open:** None — documented; reviewer must verify `Broker::get<AppT>` generic iteration without switch.

49. ★ **Layout `weight`/`rowSpan=0` & `contentScale` rounding determinism (EOL HiDPI — was vague):** Q34 left `weight` distribution (flex vs equal) and `rowSpan=0` (fill remainder) vague. **Fixed (binding, `persistence.md` §10.5 + `modules.md` RHI):** `weight` = flex (remaining space after fixed `span` weights) with `rowSpan==0` = fill remainder; equal weights → equal distribution; `Layout::resolve(framebufferSize,contentScale)` uses `floor(framebufferSize * weight/sumWeights)` with remainder to last view (deterministic, avoids 1-px gaps on HiDPI). `contentScale` from `glfwGetWindowContentScale` per monitor (web.dev high-dpi). **Open:** None — pinned.
